# SmartSale: отгрузка заказов (АРМ №4)

Внешняя обработка для оператора/склада: создаёт `РеализацияТоваровУслуг` **на
основании** заказов клиентов (`ЗаказКлиента`), оформленных агентами SmartSale.
Заполнение — штатное (`РеализацияОбъект.Заполнить(Заказ)`), каждый заказ —
отдельной транзакцией: ошибка одного не срывает остальные.

## Что делает
1. По отбору (период, агент/менеджер, статус) выводит проведённые заказы.
2. Оператор отмечает нужные флажком.
3. Кнопка «Создать реализации» — по каждому отмеченному:
   - защита от повторной отгрузки (если по заказу уже есть реализация — пропуск);
   - опц. перевод заказа в статус «К отгрузке» (флаг, по умолчанию выкл.);
   - `Заполнить(заказ)` → опц. проведение;
   - результат построчно в колонке и в протоколе.

## Сборка `.epf`
```
powershell -File "C:\Users\User\Desktop\шероз\Обработки\ERP\build.ps1" `
  -Name SmartSale_ОтгрузкаЗаказов `
  -Srvr "localhost\erp_test" `
  -Platform "C:\Program Files\1cv8\8.3.27.2130\bin\1cv8.exe"
```
Требуется запущенная служба «Агент сервера 1С:Предприятия 8.3 (x86-64)» (база
`erp_test` серверная). Загрузка из XML базу НЕ меняет. Платформа и путь базы
могли смениться — см. `build.ps1`.

## Загрузка/запуск в УТ (ut milk)
- Открыть `.epf` через «Файл → Открыть» в 1С:Предприятии, ЛИБО подключить как
  дополнительную обработку (в модуле объекта есть `СведенияОВнешнейОбработке`).
- Права: реализация проводится под учёткой оператора — нужны права проведения
  `РеализацияТоваровУслуг`.

## Структура исходников
- `xml/` — метаданные обработки (корень + форма).
- `МодульОбъекта.bsl` — сведения для регистрации доп.обработки.
- `Форма/Модуль.bsl` — вся логика формы.

## Открытые вопросы (к обсуждению)

  заказам» обычно ждёт «К отгрузке». Проверить на erp_test/ut milk, нужен ли флаг
  «установить К отгрузке» или отдельное согласование.
- Проводить сразу или создавать черновиком (флаг «Проводить созданные реализации»).
- Роль/права оператора.
