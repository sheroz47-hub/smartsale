# SmartSale: формирование MML (АРМ №3)

Внешняя обработка: задаёт **обязательный ассортимент (MML)** формата магазина
ТИПОВЫМ механизмом — документом `ИзменениеАссортимента`, наполняющим регистр
`Ассортимент`. Роль строки `ПостоянныйАссортимент` = must-stock.

## Что делает
1. Выбираешь **формат магазина** и роль (по умолчанию «Постоянный ассортимент»).
2. «Подобрать товары» (фильтр по имени) → таблица номенклатуры с флажками.
3. «Добавить в ассортимент» → создаётся один `ИзменениеАссортимента`
   (ОбъектПланирования = формат, операция «Изменение в ассортименте», строки с
   выбранной ролью) и (опц.) проводится → товары попадают в регистр `Ассортимент`
   формата.

## ⚠ Предпосылки (сделать ДО запуска)
- **Включить опцию `ИспользоватьАссортимент`** (НСИ и администрирование →
  раздел ассортимента). Сейчас в ut milk выключена.
- Завести **форматы магазинов** (каналы сбыта).
- Привязать клиентов к форматам (доп.сведения) — отдельный шаг для выгрузки MML
  на телефон.

## Не проверено вживую
Обработка собрана и синтаксис чист, но проведение `ИзменениеАссортимента` и
обязательные поля (стадия и т.п.) зависят от настройки подсистемы — протестировать
после включения опции и заведения форматов. `Заполнить(Неопределено)` ставит
умолчания; если проведение потребует доп. полей — поправим по протоколу ошибки.
