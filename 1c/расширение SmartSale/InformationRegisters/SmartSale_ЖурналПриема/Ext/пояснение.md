# Регистры расширения SmartSale — как создать в Конфигураторе

XML метаданных для регистров не прикладываю: у регистра сведений в выгрузке
десятки обязательных секций, собранный вслепую файл труднее проверить, чем
создать объект тремя действиями мышью. Структура обоих регистров тривиальна.

## Регистр сведений `SmartSale_СкладыАгентов`

Связь «пользователь-агент → его организация, склад и подразделение».
Определяет, на какую организацию/склад проводится заказ и по какому складу
агент видит остатки.

Агент указывается в запросе параметром `agent` (сервер SmartSale — доверенный
посредник, он сам подставляет нужного агента). По этому агенту сервис берёт
склад: чужой склад агенту не покажется. Организация вынесена сюда потому, что
у складов в этой базе нет привязки к организации.

- Назначение: **Независимый**, периодичность **Непериодический**.
- Измерение: `Пользователь` — СправочникСсылка.Пользователи, **ведущее**.
- Ресурс: `Организация` — СправочникСсылка.Организации.
- Ресурс: `Склад` — СправочникСсылка.Склады.
- Ресурс: `Подразделение` — СправочникСсылка.СтруктураПредприятия.
- Ресурс: `Касса` — СправочникСсылка.Кассы (для приёма оплат в ПКО).
- Ресурс: `Логин` — Строка 64 (вход агента в приложение SmartSale).
- Ресурс: `Пароль` — Строка 100 (временный пароль агента; хранится в открытом
  виде — это внутренняя учётка приложения, ротация через смену здесь).

Заполняется вручную (Операции → Регистр сведений → SmartSale_СкладыАгентов):
по строке на каждого агента. Один агент — один склад и одна касса.
Валюта кассы должна совпадать с валютой управленческого учёта (UZS).

`Логин`/`Пароль` — онбординг агента: сервис отдаёт их методом `/meta`
(массив `agent_accounts`), сервер SmartSale выставляет агенту логин и хеш
пароля, и агент входит в приложение этими логином/паролем. Пусто — агент
в приложение не входит. Пароль — временный, сообщается агенту; смена — правкой
здесь (при следующем обмене подхватится). УТ здесь ведущий: значение отсюда
перезаписывает пароль в SmartSale на каждом обмене.

## Регистр сведений `SmartSale_Токены`

Токены авторизации канала SmartSale → УТ. Сервер SmartSale шлёт токен
заголовком `X-SmartSale-Token: <токен>` (свой заголовок, а не `Authorization`:
тот занят Basic-аутентификацией публикации). Хранится SHA-256 токена, а не сам
токен: утечка регистра не даёт действующего токена, как и с паролями.

- Назначение: **Независимый**, периодичность **Непериодический**.
- Измерение: `Хеш` — Строка 64, **ведущее** (SHA-256 в hex, нижний регистр).
- Ресурс: `Наименование` — Строка 100 (кому выдан, для учёта).
- Ресурс: `Активен` — Булево (снять флаг = отозвать токен).

Заполняется скриптом `выпустить-токен.ps1`: он генерирует токен, печатает
его hex-хеш для записи в регистр и сам токен для настройки SmartSale.
Токен показывается один раз и в базе не хранится.

## Регистр сведений `SmartSale_ЖурналПриема`

Идемпотентность приёма документов из SmartSale. Приложение шлёт у каждого
документа `client_uid` — телефон генерирует его при создании. Связь на
рынке рвётся посреди отправки, приложение повторяет запрос, и без этого
журнала в базе появились бы дубли заказов.

- Назначение: **Независимый**, периодичность **Непериодический**.
- Измерение: `КлючИдемпотентности` — Строка 36, **ведущее**.
- Ресурс: `Документ` — составной тип:
  ДокументСсылка.ЗаказКлиента, ДокументСсылка.ПриходныйКассовыйОрдер.
- Ресурс: `Принят` — Булево.
- Ресурс: `Номер` — Строка 32.
- Ресурс: `Ошибка` — Строка (неограниченная).
- Ресурс: `ДатаПриема` — Дата (дата и время).

Заполняется только кодом приёма. Вручную не трогать.

## Регистр сведений `SmartSale_Маршруты`

Маршрут агента: по каким клиентам он ходит в какой день недели. Ведётся в УТ
(взамен кабинета SmartSale), отдаётся методом `/meta` (массив `agent_routes`)
и приезжает в приложение как маршрут по дням.

- Назначение: **Независимый**, периодичность **Непериодический**.
- Измерение: `Пользователь` — СправочникСсылка.Пользователи (агент), **ведущее**.
- Измерение: `ДеньНедели` — Число (1, 0): 1 — понедельник, 7 — воскресенье
  (ISO, как на сервере), **ведущее**.
- Измерение: `Партнер` — СправочникСсылка.Партнеры (клиент точки), **ведущее**.
- Ресурс: `Порядок` — Число (5, 0): порядок обхода в дне (меньше — раньше).

Заполняется в УТ (обработкой/формой либо списком регистра): по строке на
«агент — день — клиент». Один клиент в дне у агента — одна строка.
