# Аудит торговой точки — объекты расширения (блок «Аудит ТТ»)

Осмотр точки по стандарту работы ТП (конкуренты, холодильники, состояние
магазина, наличие ЛПР и т.п.). Вопросы аудита **настраиваются в УТ**, агент
проходит аудит на визите в приложении, ответы возвращаются в УТ и складываются
в регистр — менеджер смотрит их в УТ (форма/обработка — отдельно).

Все объекты — назначение **Собственный** (ObjectBelonging = Native), префикс
`SmartSale_`.

## 1. Перечисление `SmartSale_ТипыОтветовАудита`

Значения (имена важны — по ним сервис отдаёт тип поля телефону):
- `Строка` — свободный текст (конкуренты, состояние магазина).
- `Число` — числовой ответ (сколько холодильников).
- `Булево` — да/нет (есть ЛПР).

## 2. Справочник `SmartSale_ВопросыАудита`

Одна запись — один вопрос осмотра. `Наименование` — короткая метка вопроса.

| Реквизит | Тип | Назначение |
|---|---|---|
| `Текст` | Строка (неогр.) | Формулировка вопроса агенту. Пусто — берётся Наименование. |
| `ТипОтвета` | ПеречислениеСсылка.SmartSale_ТипыОтветовАудита | Как отвечать (тип поля на телефоне). |
| `Порядок` | Число | Порядок вопросов в анкете. |
| `Активен` | Булево | В выгрузку идут только активные. |
| `Обязательный` | Булево | Обязателен ли ответ (проверяет приложение). |

## 3. Регистр сведений `SmartSale_РезультатыАудита`

Непериодический, независимый. Одна запись — один ответ на один вопрос в рамках
одного прохода аудита.

| Поле | Вид | Тип | Назначение |
|---|---|---|---|
| `КлючАудита` | Измерение | Строка (36) | uuid прохода аудита с телефона (группирует ответы, ключ идемпотентности). |
| `Вопрос` | Измерение | СправочникСсылка.SmartSale_ВопросыАудита | На какой вопрос ответ. |
| `Ответ` | Ресурс | Строка (неогр.) | Ответ агента (число/да-нет тоже строкой). |
| `Клиент` | Реквизит | СправочникСсылка.Партнеры | Точка. |
| `Агент` | Реквизит | СправочникСсылка.Пользователи | Кто проводил. |
| `Дата` | Реквизит | Дата (Дата и время) | Когда. |

Приём пишет НАБОРОМ по `КлючАудита` с замещением: повтор доставки одного
аудита перезаписывает его строки, дублей нет.

## Обмен

- Сервис отдаёт активные вопросы методом `/meta` (массив `audit_questions`:
  uid, text, answer_type, order, required). Приложение строит из них форму.
- Результат приложение возвращает методом `POST /audits`, тело
  `{"audits":[{client_uid, customer_uid, agent_uid, date, answers:[{question_uid, value}]}]}`.
  Обработчик `SmartSale_Обмен.ПринятьАудиты` пишет регистр.

## Права

Роли `smartsale` — **чтение** `SmartSale_ВопросыАудита` (для выгрузки). Запись
регистра `SmartSale_РезультатыАудита` идёт под **привилегированным режимом**
(безопасный режим с расширения снят), прав на регистр учётке выдавать не нужно.
