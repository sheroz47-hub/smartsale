# Акции SmartSale — объекты расширения для Конфигуратора

Этап 3 обмена: условия акций настраиваются в УТ (в расширении), а считает их
движок в приложении SmartSale. Здесь описаны объекты, которые нужно создать в
конфигурации расширения. XML не прикладываю: у справочника с двумя табличными
частями и перечисления в выгрузке много обязательных секций, собранный вслепую
файл труднее проверить, чем создать объект мышью.

Все объекты — назначение **Собственный** (ObjectBelonging = Native), имена с
префиксом `SmartSale_`.

## Перечисление `SmartSale_ВидыМеханикиАкций`

Как считается скидка. Значения (именно такие имена — на них ссылается код):

- `Процент` — простая процентная скидка на отобранные товары.
- `Объем`  — ступенчатая скидка от объёма (пороги по количеству/сумме).
- `Бонус`  — бонусный товар «купи N — получи M бесплатно».

Создание: Перечисления → добавить `SmartSale_ВидыМеханикиАкций` → на вкладке
«Данные» добавить три значения с именами `Процент`, `Объем`, `Бонус`.

## Справочник `SmartSale_Акции`

Одна запись — одна акция. Наименование — стандартный реквизит (название акции).

### Реквизиты шапки

| Имя | Тип | Назначение |
|---|---|---|
| `Активна` | Булево | Выключатель без удаления. В выгрузку идут только активные. |
| `ДатаНачала` | Дата (состав «Дата») | Начало действия. Пусто = без нижней границы. |
| `ДатаОкончания` | Дата (состав «Дата») | Конец действия. Пусто = бессрочно. |
| `ВидМеханики` | ПеречислениеСсылка.SmartSale_ВидыМеханикиАкций | Процент / Объём / Бонус. |
| `Сегмент` | СправочникСсылка.СегментыПартнеров | Кому. Пусто = всем клиентам. |
| `Приоритет` | Число (3, 0) | При пересечении акций на одном товаре приложение берёт с бóльшим приоритетом. |
| `Процент` | Число (6, 2) | Для механики **Процент**: величина скидки. |
| `КупитьКоличество` | Число (15, 3) | Для механики **Бонус**: N (сколько купить). |
| `БонусныйТовар` | СправочникСсылка.Номенклатура | Для механики **Бонус**: что даём бесплатно. |
| `БонусноеКоличество` | Число (15, 3) | Для механики **Бонус**: M (сколько бесплатно). |

### Табличная часть `Товары`

На какие товары распространяется акция. Для **Процент** и **Объём** — товары
скидки; для **Бонус** — товары-условие (их покупка даёт бонус).

| Имя | Тип | Назначение |
|---|---|---|
| `Номенклатура` | СправочникСсылка.Номенклатура | Товар или **группа** (ЭтоГруппа = Истина — тогда акция на всю группу). |

### Табличная часть `Пороги`

Только для механики **Объём**. Ступени скидки. Приложение берёт наибольший
подходящий порог (по количеству или сумме товаров акции в заказе).

| Имя | Тип | Назначение |
|---|---|---|
| `МинКоличество` | Число (15, 3) | Порог по количеству (сумма кол-ва товаров акции в заказе). 0 = не по количеству. |
| `МинСумма` | Число (15, 2) | Порог по сумме. 0 = не по сумме. |
| `Процент` | Число (6, 2) | Скидка на этой ступени. |

## Как заполнять (примеры)

- **Процент**: ВидМеханики = Процент; Процент = 10; в «Товары» — товар/группа.
  → 10 % на эти товары.
- **Объём**: ВидМеханики = Объём; в «Товары» — товары; в «Пороги» строки:
  (МинКоличество 10 → 5 %), (МинКоличество 20 → 8 %). → от 10 шт — 5 %, от 20 — 8 %.
- **Бонус**: ВидМеханики = Бонус; КупитьКоличество = 10; БонусныйТовар = X;
  БонусноеКоличество = 1; в «Товары» — товары-условие. → на каждые 10 купленных
  единиц из «Товары» одна X бесплатно (в УТ ляжет строкой X со 100 % скидкой).

## После создания

Дать роли расширения право чтения на `SmartSale_Акции` и
`SmartSale_ВидыМеханикиАкций` (сервис отдаёт их методом `/promotions`), затем
обновить конфигурацию и загрузить модуль сервиса с методом `/promotions`.
