# Задания агентов SmartSale — объект расширения для Конфигуратора

Фаза B эпика «маршруты и задания». Задания ставятся в УТ (агенту по клиенту),
приезжают в приложение, агент отмечает выполнение с комментарием, и отметка
возвращается в УТ. Фотоотчёт и локация — следующая фаза (C).

Объект — назначение **Собственный** (ObjectBelonging = Native), префикс
`SmartSale_`.

## Справочник `SmartSale_Задания`

Одна запись — одно задание агенту. `Наименование` — стандартный реквизит
(краткий заголовок задания, необязательно).

### Реквизиты

| Имя | Тип | Назначение |
|---|---|---|
| `Агент` | СправочникСсылка.Пользователи | Кому задание. |
| `Клиент` | СправочникСсылка.Партнеры | По какому клиенту (точке). |
| `Дата` | Дата (состав «Дата») | На какую дату/до какой. Пусто — без срока. |
| `Текст` | Строка (неограниченная) | Что сделать. |
| `Выполнено` | Булево | Отметка выполнения (ставит обмен от агента). |
| `ДатаВыполнения` | Дата (состав «Дата и время») | Когда выполнено. |
| `КомментарийВыполнения` | Строка (неограниченная) | Отчёт агента (в фазе C сюда же — фото/локация). |
| `Активно` | Булево | Выключатель. В выгрузку идут активные и невыполненные. |

### Как заполнять

Ставится в УТ (обработкой/формой либо списком справочника): агент, клиент,
дата, текст. `Выполнено`/`ДатаВыполнения`/`КомментарийВыполнения` — НЕ трогать
вручную: их ставит обмен, когда агент отметит выполнение в приложении.

## Обмен

- Сервис отдаёт активные невыполненные задания методом `/meta` (массив
  `agent_tasks`): uid, агент, клиент, дата, текст. Сервер SmartSale раскладывает
  их по агентам, телефон показывает у клиента.
- Отметку выполнения приложение возвращает обратным каналом: метод `POST
  /tasks` расширения ставит `Выполнено`, `ДатаВыполнения`, `КомментарийВыполнения`.

## Права

Дать роли расширения (учётке `smartsale`) **чтение и изменение**
`SmartSale_Задания`: чтение — для выгрузки, изменение — чтобы обмен проставлял
отметку выполнения.

## Фотоотчёт (фаза C)

Фото, снятое агентом при отметке выполнения, приезжает через сервер-шину и
прикладывается как **присоединённый файл к КЛИЕНТУ задания** (Справочник.Партнеры
уже владелец присоединённых файлов — «скрепка» карточки партнёра), в томе
хранения по дате. Отдельный справочник присоединённых файлов НЕ создаётся.
В описании файла — ссылка на задание (текст и дата), чтобы отчёт был опознаваем
в общем списке файлов клиента. Метод сервиса `POST /tasks/photo?task=<uid
задания>&name=<uuid снимка>`, тело — jpeg бинарём; обработчик
`SmartSale_Обмен.ОтметитьЗаданиеФайлом` находит клиента задания и прикладывает
файл. Добавление файла идёт под **привилегированным режимом** (безопасный режим
с расширения снят), поэтому прав на присоединённые файлы/том учётке `smartsale`
выдавать не требуется. Идемпотентно по имени файла: повтор одного снимка второй
файл не создаёт.

Координаты клиента (кнопка «уточнить координаты» в приложении) — метод `POST
/customers/geo`, пишутся в контактную информацию головного контрагента партнёра
(виды `ГеографическаяШирота`/`ГеографическаяДолгота`, тип «Другое»), тоже под
привилегированным режимом.
